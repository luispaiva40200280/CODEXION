##  Description
Codexion is a multi-threaded simulation modeling developers sharing limited computing resources. Coders sit in a circle and alternate between compiling, debugging, and refactoring. Compiling requires acquiring two shared USB dongles simultaneously. The core objective is to orchestrate concurrent resource access using POSIX threads, preventing deadlocks and developer burnout before a deadline.
## Instructions

### Thread Synchronization MechanismsStrict POSIX:
primitives govern all shared memory states to prevent race conditions.  Mutexes (pthread_mutex_t): 
Each dongle is protected by a dedicated mutex to guarantee exclusive physical access. A central write_lock serializes terminal output, ensuring timestamped log messages never visually interleave.  Condition Variables (pthread_cond_t): Coders rely on condition variables linked to dongle availability, preventing heavy CPU polling. Targeted broadcasts awaken specific adjacent threads precisely when resources are released.  Blocking Cases HandledThe concurrency architecture is built to withstand high-contention edge cases.  Deadlock Prevention: Circular wait conditions (Coffman's conditions) are neutralized by enforcing strict, unidirectional lock acquisition hierarchies and utilizing pthread_mutex_trylock to gracefully retreat when secondary resources are locked.  Starvation & Cooldown: A priority heap strictly enforces either FIFO or EDF (Earliest Deadline First) scheduling policies for fair arbitration. Dongles physically reject immediate re-acquisition until their mandatory dongle_cooldown expires.  Precise Burnout Detection: A dedicated monitor thread continuously sweeps coder execution timestamps, accurately halting the simulation and triggering burnout logs within the mandatory 10ms threshold.  ResourcesDocumentation: POSIX Threads (pthreads) standard manuals and Valgrind/Helgrind documentation for concurrency analysis.  AI Usage: Artificial Intelligence was utilized to analyze Helgrind Lock Order Violation graphs, optimize peak concurrency by diagnosing thundering-herd wakeup storms, and audit priority heap inversion bugs.
